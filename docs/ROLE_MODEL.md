# Модель ролей Gaido

Користувач може мати кілька ролей одночасно. Ролі живуть у `users.roles` (масив), не в окремій таблиці.

| Роль | Сайт | Хто це |
|------|------|--------|
| `ROLE_TOURIST` | усі | звичайний користувач |
| `ROLE_GUIDE` | svit.gaido-ua.com | гід / екскурсовод |
| `ROLE_PROVIDER` | servis.gaido-ua.com | автор оголошень (майстер, перекладач, лікар…) |
| `ROLE_CARRIER` | vezu.gaido-ua.com | перевізник |
| `ROLE_MODERATOR` | усі | модерація контенту свого контуру |
| `ROLE_ADMIN` | усі | повний доступ; успадковує модератора (Casbin `g`) |

Перекладач, який також проводить екскурсії: `ROLE_TOURIST` + `ROLE_PROVIDER` + `ROLE_GUIDE`. Перевізник не отримує `ROLE_PROVIDER`, навіть якщо в БД є рядок у `providers` (спільна таблиця профілів). На той самий акаунт можна повісити іншу вертикаль: заповнити профіль гіда на svit (`ROLE_GUIDE`) або профіль перевізника на vezu (`ROLE_CARRIER`).

## Адмінки по сайтах

Одна панель (`AdminPages`), вкладки фільтруються за `getSiteMode()`:

| | gaido-ua.com | svit | vezu | servis |
|---|---|---|---|---|
| Аналітика, користувачі, налаштування, контент, журнал, аудит | ✓ | | | |
| Гіди, екскурсії, відгуки | ✓ | ✓ | | |
| Перевізники, рейси | ✓ | | ✓ | |
| Автори оголошень, оголошення, скарги | ✓ | | | ✓ |

На головному порталі — зведення всіх вертикалей. На svit / vezu / servis — лише свій контур.

## API

Адмін: `/api/v1/admin/*` — лише `ROLE_ADMIN`.  
Модератор: `/api/v1/moderator/*` — `ROLE_MODERATOR` (і адмін через inherit).  
Кабінет гіда / перевізника / автора — окремі шляхи в `policy.csv`.

Міграція `000063_split_carrier_role.sql`: усі з `carrier_profiles` отримують `ROLE_CARRIER`; `ROLE_PROVIDER` знімається, якщо немає `service_offerings`.
